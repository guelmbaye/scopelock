Features and acceptance criteria

Sample Preload and Load Sample

The sample is visible on first open. No check runs until the user presses Check Alignment. Load sample is secondary and sits near the workspace heading.

  • First load: both panes show the sample, and the result reads "Ready to check".
  • Load sample restores both panes exactly and resets the result.
  • Load sample is visually secondary to Check Alignment.
Alignment Check

One verdict per check: Aligned · Proceed, Unplanned · Review plan, or Conflict · Stop, plus a short explanation, labeled as product alignment.

  • Unedited sample → Conflict · Stop.
  • Line moved Later → Now, same diff → Aligned · Proceed.
  • Every result has a verdict word, an action, and an explanation.
Evidence Verification

Exactly one proposed evidence item: an exact quote plus its full heading path. Both must verify, otherwise the result falls back to Unplanned with a secondary Evidence check note.

  • Aligned and Conflict always show a quote found verbatim under its stated path.
  • Wrong path → Unplanned plus a note naming the claimed location and where the quote actually is.
  • Quote not found → Unplanned plus a note saying the quote wasn't found.
  • Unrelated diff → Unplanned plus "No relevant planning decision was found for this change."
Technical Quality Labeling

No fake test, build, or CI signals. The sample diff is framed as known-working. Any other diff is "Technical quality: not evaluated".

  • Sample label shows only while the diff matches the sample.
  • Edited diff → "Technical quality: not evaluated".
  • No test, build, or CI status anywhere.

States

Now vs deferred

Building now

  • One page: plan pane, diff pane, Check Alignment, result
  • Preloaded canonical sample and Load sample
  • One verdict, explanation, and one evidence item
  • Quote plus full-heading-path verification, with Unplanned fallback
  • Technical-quality labeling
  • Checking (inputs locked), outdated, empty-input, and check-failed states

Deferred / non-goals

  • Mixed or multi-change diffs
  • Multiple evidence items or ranking
  • Repo, CLI, or file loading; PR, CI, IDE, or agent hooks
  • Saving inputs or history
  • Code review, bug or security checks, any tech-quality indicator
  • PM features, chat, conversational UI

Resolved in review

Editing after a verdict. The verdict goes outdated immediately ("Inputs changed — check again"), with no auto-rerun. Inputs are locked while a check runs. There are no open product questions.

Build-time copy detail

Rejection wording. The behavior is fixed: the note must distinguish "quote not found" from "quote found outside the claimed heading path" (and name where it was found). Only the exact copy is left for the build.

Honest read

The journey is complete and closes cleanly on the flip test. Every behavior has checkable criteria you can verify by looking at the screen. The now/deferred split is strong: one evidence item and no technical signal keep the proof narrow. The what-ifs are resolved: "check failed" is separate from "Unplanned", and stale verdicts can't survive an edit.
