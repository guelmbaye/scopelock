SCOPELOCK — Technical Spec

Canonical source: devpost/spec.md. This page helps you review it; it isn't part of the product.

1 · The shape: three parts, one trust boundary

The page collects input and shows state. The server asks Claude for a proposal. The verifier decides, with no AI, whether that proposal counts as evidence. The model and verifier modules never import each other; check.js joins them.

2 · Core journey through the system

Step through prd.md > The Core Journey and see which file handles each step.

3 · How the server decides the final verdict

src/check.js can only downgrade the model's verdict, never upgrade it or reinterpret it.

The schema already forbids the two invalid rows. If one arrives anyway, it is rejected, never repaired.

6 · Components

Model adapter src/model.js

The only file that imports @anthropic-ai/sdk. The model comes from ANTHROPIC_MODEL (default claude-opus-5-5). It calls client.messages.parse() with output_config.format: jsonSchemaOutputFormat(PROPOSAL_SCHEMA) (from @anthropic-ai/sdk/helpers/json-schema), effort medium, a 60s timeout and 1 retry.

Schema: a top-level object { proposal } whose proposal is two anyOf branches (the SDK 0.133.0 helper requires a top-level type: "object"). Aligned/conflict require evidence {quote, headingPath[]}; unplanned requires evidence to be null. It checks stop_reason first, then reads message.parsed_output.proposal, then runs a defensive branch check. Refusal, truncation, missing output or an impossible combination throws, which becomes check_failed.

The prompt requires the complete block text, copied exactly with the leading marker removed and inline Markdown kept, plus a full outer-to-inner heading path and a worked example. Implements prd.md › Alignment Check, Evidence Verification.

Plan parser src/markdown-blocks.js

parsePlan(text) → [{text, path}]. ATX headings only, using a normal stack. A block is a paragraph or a list item with indented continuation lines. Only the leading - * + 1., [ ] and > are stripped. Fenced code is ignored, setext headings are treated as text, and blocks before any heading get path [].

normalize: CRLF → LF, collapse spaces/tabs/newlines, trim. Nothing else. Implements prd.md › Evidence Verification.

Verifier src/verify.js

Whole-block equality, then the exact path among the matches. It returns ok, quote_not_found, or wrong_path with the paths where the quote was actually found. Duplicates pass if any occurrence matches the claimed path.

Orchestrator src/check.js · Server server.js

createApp({model}) lets tests inject a mock. Responses: 200 verdict · 400 invalid_input · 502 check_failed. The server listens on PORT||3000. A missing key logs a warning and checks then fail cleanly.

Page public/ · Sample public/sample.js

Plain HTML/CSS/JS. sample.js exports SAMPLE_PLAN (# Scope › ## Now / ## Later with "Export results as CSV") and SAMPLE_DIFF. The page and the tests both import it.

Live smoke checks scripts/smoke-live.js

npm run smoke, manual only. It runs cases 1, 2, 3 and 6 against the real API, 3 times each (about 12 calls, well under $1). Bar: the flip test passes 3/3. If it misses, fix the prompt and never the verifier. Next lever: annotate each plan block with its computed path in the prompt.

10 · Decisions & the open question

Your hypothesis to validate: can the model reliably return the complete block and the exact full path under this strict contract? The verifier is pinned by tests; the model is measured by smoke checks. If it is unreliable, the first response is the prompt, never a looser verifier.

Known boundary: the verifier checks where the quote sits, not whether that location fits the verdict (e.g. Aligned citing a Later line). By design, that interpretation belongs to the model; the smoke checks watch for it.

Accepted at review: fenced code ignored · setext treated as text · no lazy list continuation · no server-side refusal fallback · effort medium · local only.

Changed at review: messages.parse() + jsonSchemaOutputFormat → parsed_output; schema branches tie evidence to the verdict, and impossible combinations become check_failed.
